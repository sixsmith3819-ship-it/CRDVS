🔄 Key Data Flows
Flow 1: Authentication & Login
  • User enters credentials (email/password)
  • Process 1 validates against Supabase Auth
  • Loads D1 (Profiles) to retrieve role & permissions
  • Checks is_active status for account validity
  • Session created; user redirected to dashboard
  • Logs login event to D8 (Audit Logs)
Flow 2: Identity Verification Search
  • User submits National ID or name for verification
  • Process 2 applies fuzzy matching algorithm
  • Queries D2 (National IDs) for exact matches
  • Queries D3 (Criminal Records) for fuzzy matches
  • Returns exact matches (confidence 100%)
  • Returns fuzzy matches (confidence 75%+)
  • Creates verification request entry in D5
  • Logs verification action to D8
Flow 3: Criminal Record Creation/Update
  • Admin/Police submits new record or update
  • Process 3 validates data completeness & format
  • Enforces role-based permissions via RLS
  • Creates/updates entry in D3 (Criminal Records)
  • Updates conviction count in D4 (Convictions)
  • Triggers Process 4 (Duplicate Detection)
  • Records action in D8 (Audit Logs)
Flow 4: Duplicate Detection & Resolution
  • Triggered after record creation/update (Process 3)
  • AI algorithm compares against all D3 records
  • Analyzes name similarity (trigram matching)
  • Checks DOB and fingerprint matches
  • Calculates overall similarity score (0-100)
  • If score > 80%: flags as potential duplicate in D6
  • Admin reviews flag and resolves (confirmed/false positive)
  • Logs resolution to D8
Flow 5: Report Generation
  • User requests report for a criminal record
  • Process 5 creates JSONB snapshot of record from D3
  • Generates SHA-256 hash for tamper detection
  • Stores report in D7 (Verification Reports)
  • Assigns unique report ID (RPT-YYYYMMDD-XXXX)
  • Includes expiration timestamp (optional)
  • User can download/view/share report
Flow 6: Admin User Management
  • Admin accesses /admin/users dashboard
  • Process 6 loads all user profiles from D1
  • Admin creates new user or updates existing
  • Validates email uniqueness and format
  • Inserts/updates entry in D1 (Profiles)
  • If creating: assigns role & initial permissions
  • If deactivating: sets is_active = false
  • Action logged to D8

🔒 Security Features & Enforcement
Database-Level Security (Row-Level Security - RLS)
✓ Automatic enforcement - Cannot be bypassed in code
✓ Per-table policies - SELECT, INSERT, UPDATE, DELETE
✓ Role-based access - is_admin() and get_user_role() functions
✓ Active user check - is_active_user() prevents deactivated account access
Audit & Compliance
✓ Immutable audit logs - D8 table: no updates/deletes allowed
✓ All actions logged - CREATE, READ, UPDATE, DELETE, LOGIN, LOGOUT
✓ Metadata captured - User ID, IP address, user agent, timestamp
✓ Snapshot storage - Old and new values stored for updates
✓ Tamper detection - Reports include SHA-256 hash
Session & Authentication
✓ Supabase Auth - Email/password with secure session management
✓ Account status enforcement - is_active check on every request
✓ Session protection - Middleware protects all routes
✓ Auto-redirect - Unauthenticated users redirected to login
